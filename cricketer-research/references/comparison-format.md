# Comparison format

Used when the user names two or more players and asks to compare them, rank them, or decide who is better. The structure keeps every claim side by side so the reader can see the basis for the verdict.

## Before writing

Do Step 0 and Step 1 from SKILL.md for every player: pin down identity, verify figures from a statistics page, stamp the date. A comparison in which one player's numbers are current and the other's are a season old is misleading, so capture both from the same kind of source on the same day.

Work out what the user is actually asking. "Compare X and Y" wants a rounded comparison. "Who's the better Test batter" wants a verdict on one format and one role, and the whole document should lean toward that. State the question you are answering in the first line.

## Structure

### Question
One sentence stating what is being compared and on what terms (format, role, era), plus the "stats as of" date and source.

### Identity header
One compact line per player: name, country, role, batting and bowling style, active or retired, span of international career. Note any disambiguation made ("Steven Smith of Australia, not Graeme Smith").

### Side-by-side statistics
One table per relevant format, players as columns:

| Tests | Player A | Player B |
|---|---|---|
| Matches | | |
| Runs | | |
| Average | | |
| Strike rate | | |
| 100s / 50s | | |
| Highest score | | |

Repeat for ODIs, T20Is, and for bowling where either player bowls. Include a franchise row (IPL or equivalent) when it matters to the comparison. Each number comes from the same date-stamped source for both players.

Add a short **splits** table when it changes the picture: home versus away, against the strongest attacks, in a particular era or period, as captain versus not. Statsguru and HowSTAT hold these but block fetching, so take them from dated news articles that quote them. Search with the current year in the query and use the newest figure you can find for each player; put the date beside every split, and say so when one player's split is older than the other's. Pick the two or three splits that bear on the user's question rather than every split available.

### Attribute ratings side by side
Use the same dimension set for every player, chosen from the role-based sets in SKILL.md and anchored to the same scale (10 = among the best ever in that dimension). One line of justification per cell, since this is where the verdict is really made. Start every cell with the score as `n/10`, then the reason, so the PDF script can draw the grouped bar chart from it.

| Dimension | Player A | Player B |
|---|---|---|
| … | n/10 — reason | n/10 — reason |

### Context that cuts both ways
Bullets on what makes raw comparison unfair in each direction: eras and pitches, bowling attacks faced, team strength around them, injuries, role in the side, how many matches in difficult conditions. A reader should finish this section knowing what each player's supporters and critics would say.

### Verdict
Answer the user's question directly, in the first sentence. Then the reasoning in a few bullets, then the conditions under which the verdict would flip ("if the question were ODIs rather than Tests", "if away record is weighted more heavily"). Do not hide behind "both are great"; the user asked for a judgement, so give one, with the evidence that drove it and the caveats that limit it.

### Sources
Numbered list with URL and access date, covering every number used.

## Three or more players
Keep the same structure with one column per player. Above four players, replace the attribute table with a ranked list per dimension and keep the statistics tables, otherwise the document becomes unreadable.
